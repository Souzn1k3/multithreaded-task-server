# Многопоточный сервер задач

Клиент-серверное приложение для управления общим списком задач.

Используемые инструменты:

- TCP-сокеты (`socket`);
- многопоточность (`threading`);
- общий изменяемый список данных (список задач хранится на сервере);
- синхронизация доступа к общим данным (`threading.Lock`).

## Состав проекта

| Файл | Назначение |
|------|------------|
| `server.py` | многопоточный TCP-сервер: хранит общий список задач и обслуживает всех клиентов |
| `client.py` | консольный клиент: подключается к серверу и отправляет команды |

## Как запустить

1. Запустите сервер (в отдельном окне терминала):

   ```
   python server.py
   ```

   По умолчанию сервер слушает `127.0.0.1:5555`. Можно указать свои адрес и порт:

   ```
   python server.py 127.0.0.1 5555
   ```

2. Запустите клиент (каждого клиента - в своём окне терминала, можно несколько сразу):

   ```
   python client.py
   ```

   Клиент по умолчанию подключается к `127.0.0.1:5555`; адрес и порт можно указать явно:

   ```
   python client.py 127.0.0.1 5555
   ```

> На Windows, если команда `python` не находится, используйте лаунчер `py`: `py server.py` и `py client.py`.

## Команды клиента

| Команда | Действие |
|---------|----------|
| `/add <text>` | добавить новую задачу |
| `/list` | показать все задачи |
| `/done <number>` | отметить задачу как выполненную |
| `/delete <number>` | удалить задачу (после удаления список перенумеровывается) |
| `/help` | показать справку по командам |
| `/quit` | завершить работу клиента |

Задачи хранятся в формате «номер, отметка выполнения, текст»:

```
1. [ ] Купить кофе
2. [x] Подготовить домашку
3. [ ] Посмотреть лекцию
```

## Как реализована одновременная работа нескольких клиентов

- Список задач один и хранится **только на сервере** (глобальный список `tasks` в `server.py`). Если клиент №1 выполнил `/add Купить кофе`, то клиент №2 после `/list` увидит эту задачу.
- Главный поток сервера в бесконечном цикле принимает подключения (`socket.accept()`).
- На каждого подключившегося клиента запускается **отдельный поток**:
  `threading.Thread(target=handle_client, args=(conn, addr), daemon=True).start()`.
  Поток читает команды своего клиента, выполняет их и отправляет ответ; клиенты работают параллельно и не блокируют друг друга.
- Клиент и сервер обмениваются текстовыми сообщениями в кодировке UTF-8: запрос - одна строка, ответ - несколько строк, заканчивающихся пустой строкой.
- Поток-обработчик является демоном и корректно завершается при разрыве соединения (в том числе при аварийном отключении клиента), поэтому сервер продолжает обслуживать остальных.

## Где и зачем используется синхронизация

Все потоки клиентов работают с одним изменяемым списком `tasks` (чтение в `list_tasks`, изменение в `add_task`, `done_task`, `delete_task`). Без синхронизации возможны **гонки данных**, например:

- два клиента одновременно вызывают `/add`: параллельные `tasks.append(...)` и вычисление `len(tasks)` могут перепутать нумерацию задач;
- один поток выполняет `/list` (обходит список в цикле), а другой в этот момент делает `/delete` (изменяет его) - результат `/list` получится искажённым;
- одновременные `/done` и `/delete` по одной задаче могут изменить список «посередине» другой операции.

Поэтому в `server.py` создана блокировка `tasks_lock = threading.Lock()`, и **каждое обращение к списку `tasks` выполняется внутри блока `with tasks_lock:`**. Блокировка гарантирует, что в каждый момент времени со списком работает только один поток: критические секции короткие (только само чтение/изменение списка), поэтому потоки не мешают работе клиентов друг другу заметным образом, а состояние списка всегда целостно и нумерация корректна.

## Обработка ошибок

Сервер не завершается с исключением при обычных ошибочных действиях пользователя. Обработаны ситуации:

- неизвестная команда (например, `/rem` или текст без `/`);
- некорректный `/add` - команда без текста задачи;
- некорректный `/done` и `/delete` - без номера, вместо номера текст или дробное число;
- несуществующий номер задачи (больше размера списка, 0 или отрицательный);
- обрыв соединения клиентом (сервер просто закрывает поток обработки);
- попытка запустить сервер на уже занятом порту (выводится понятное сообщение вместо падения).

Клиент тоже не падает: он корректно сообщает о недоступности сервера, обрыве соединения, а `Ctrl+C`/`Ctrl+Z` (конец ввода) завершает его штатно через `/quit`.
